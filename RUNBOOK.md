# RUNBOOK — пошаговый прогон

Готового ESPHome Kickstart для `rtl8720cf` **не существует** (запрос
[issue #17](https://github.com/libretiny-eu/esphome-kickstart/issues/17) открыт,
в релизах только ESP32/BK7231). Но он и не нужен: у вас уже есть рабочая сборка
ESPHome под эту плату — берём образ из неё.

## 1. Взять образ OTA-слота из своей сборки

На машине, где собирается ESPHome:

```bash
esphome compile eltexplug1.yaml
ls -la .esphome/build/eltexplug1/.pioenvs/eltexplug1/ | grep -iE 'image_firmware|\.bin|uf2'
```

Нужен **`image_firmware_is.0x0?????.bin`** (напр. `image_firmware_is.0x00C000.bin`) —
это образ FW-слота AmebaZ2. Проверено по исходникам LibreTiny 1.4.0
(`builder/family/realtek-ambz2.py`): для RTL8720CF собирается **один** такой файл и он
идёт и в ota1, и в ota2 — раздельных `*.ota1.bin`/`*.ota2.bin` у ambz2 **нет** (имена
`image_rtl8720cf_app.ota2.bin` — из ambz1/beken, не для этого чипа).
**Ловушка:** `firmware.bin` — тоже **UF2-контейнер** (внутри магия `UF2
`), а вовсе не
образ флеша; он побайтово равен `firmware.uf2`. Полный образ флеша — это
`image_flash_is.0x000000.bin`. Ни один из трёх для OTA не годится; скрипт их отсеивает
(обойти — `--force`).

Реальная сборка (ESPHome 2024.12.4, плата `992k`) даёт ровно такой набор:

```
image_firmware_is.0x00C000.bin   575 492  <- ЭТОТ, образ FW-слота
image_flash_is.0x000000.bin      624 644     полный образ флеша (таблица разделов)
image_bootloader.0x004000.bin     32 672     загрузчик
firmware.bin / firmware.uf2    1 227 264     UF2-контейнеры (одинаковые)
```

> **Раскладка слотов: для «по воздуху» нужен `992k`, а не `896k`.**
> При OTA заводская таблица разделов не переписывается — образ ложится в заводской
> FW2, значит его смещения/размер обязаны совпадать с заводскими. По исходникам
> LibreTiny (`boards/_base/`) у RTL8720CF ровно две раскладки, и они подписаны:
>
> | плата | ota1 | ota2 | шаг | подпись в LibreTiny |
> |---|---|---|---|---|
> | `...-2mb-896k` | `0x010000` | `0x0F0000` | `0xE0000` | **Tuya default** for CF |
> | `...-2mb-992k` | `0x00C000` | `0x104000` | **`0xF8000`** | **SDK default** for CF |
>
> Прошивка Eltex — сток Realtek SDK, и в вашем дампе слоты разнесены на **`0xF8000`**.
> Значит заводская раскладка — **992k (SDK default)**. `896k` в `eltexplug1.yaml` — это
> Tuya-раскладка, которую LibreTiny прописал уже прошитой по проводу розетке (при полной
> прошивке таблица разделов переписывается, поэтому там 896k и работает). Для OTA-пути
> собирать надо под **`generic-rtl8720cf-2mb-992k`** — для этого в проекте лежит готовый
> `eltexplug-ota.yaml`. Всё равно сверьте смещения по дампу с `0x0` перед заливкой.

## 1b. Патч LibreTiny, если сборка падает на `sys_now`

На связке ESPHome 2024.12.4 + LibreTiny сборка с `web_server:`/`captive_portal:`
(они тянут AsyncTCP) падает так:

```
lwip/sys.h:447: error: conflicting declaration of 'u32_t sys_now()' with 'C' linkage
libretiny/cores/realtek-ambz2/base/config/lwipopts.h:10: note: previous declaration with 'C++' linkage
```

Причина: LibreTiny переименовывает `sys_now` из SDK и объявляет её заново, но это
объявление попадает в **C++-линковку**, тогда как lwip объявляет её внутри `extern "C"`.
Типы совпадают (`unsigned long` == `u32_t`), расходится только линковка.

Правка — в файле
`~/.platformio/platforms/libretiny/cores/realtek-ambz2/base/config/lwipopts.h`
обернуть последнюю строку:

```c
#ifdef __cplusplus
extern "C" {
#endif
extern unsigned long sys_now(void);
#ifdef __cplusplus
}
#endif
```

Проверено: после правки `eltexplug-ota.yaml` собирается целиком с `web_server` и
`captive_portal` (flash 60.5% от 1015808 б, образ 631 364 б). Рядом положен бэкап
`lwipopts.h.orig-backup`.

> Патч живёт в установленной платформе, а не в проекте: он затрагивает все сборки
> под rtl87xx на этой машине и слетит при обновлении или переустановке платформы.

## 2. Развернуть инструмент на машине с Wi-Fi

Провижининг и `--scan` требуют Wi-Fi-адаптера, который умеет подключаться к точке
розетки; подойдёт тот же адаптер, что и для tuya-cloudcutter. На Linux нужен
`nmcli`, на Windows — `netsh`. Зависимостей у ядра нет:

```bash
python3 -c "import sys; print(sys.version)"      # нужен 3.8+
```

## 3. Сухой прогон (без розетки) — убедиться, что всё живо

```bash
python3 test_e2e.py 56684 1883 5 &          # эмулятор розетки
python3 eltex_cutter.py --fw ВАШ_ОБРАЗ.bin --ssid Home --host-ip 127.0.0.1 \
                        --device-ip 127.0.0.1 --node-id plug1 --wait 20
```

Ожидаемо: `HELLO` → `CONFIG принят` → `SUBSCRIBE` → `команда сработала` →
в логе HTTP видно `GET` образа.

## 4. Боевой прогон

Последовательность, проверенная на живой розетке. Запускалось с Windows-станции
(Ethernet и свободный Wi-Fi одновременно); домашняя сеть — это подсеть `192.168.4.x`.

**1. Пароль точки — из QR-кода на корпусе.** Он не выводится вручную из S/N:

```
WIFI:T:WPA;ELTXMAC:0CEE20000000;S:ELTEX-SW-PLG01-000000;P:Fc00000000;;
```

Пароль = серийный номер в **смешанном регистре** (`Fc00000000`, а не `FC00000000`) — перебор
вариантов из S/N именно поэтому и проваливается. Точка WPA2, открытой ветки нет.

**2. Подключиться к точке розетки.** Её адрес в своей AP — **`10.24.83.55`**
(не `192.168.43.1`), шлюз он же. Порт `56684` открыт и сразу шлёт кадр `00 00 00 33`.

**3. Провижининг без OTA** — убедиться, что розетка уходит в сеть и приходит на брокер:

```bash
python3 eltex_cutter.py --ssid ДОМ --password ПАРОЛЬ \
    --host-ip 192.168.4.33 --device-ip 10.24.83.55 --node-id plug2
```

**4. Вернуться в домашнюю сеть**, проверить, что IP совпал с тем, что обещали брокеру,
и открыть порты (на Windows — правило для профиля Public):

```bash
powershell -Command "New-NetFirewallRule -DisplayName 'eltex-cutter (temp)' -Direction Inbound -Protocol TCP -LocalPort 1883,8000 -Profile Public -Action Allow"
```

**5. OTA:**

```bash
python3 eltex_cutter.py --fw image_firmware_is.0x00C000.bin --skip-provision \
    --host-ip 192.168.4.33 --node-id plug2 --try-variants
```

Команда ушла в `sys/cmd/plug2`, розетка сделала `GET` образа (200) и перепрошилась.
Через ~минуту на её адресе поднялись **80** (web_server) и **6053** (API ESPHome),
а заводской `56684` пропал.

> Осторожно с сухими тестами: брокер по умолчанию слушает `0.0.0.0`, и настоящая
> розетка из сети может подключиться к нему и получить тестовую команду. Для сухих
> прогонов обязательно `--bind 127.0.0.1`.

## 5. Что смотреть, если не пошло

| симптом | что это значит |
|---|---|
| не подключается к `:56684` | розетка не в режиме настройки, либо другой `--device-ip` |
| `CONFIG` принят, но розетка не пришла на брокер | не тот `--host-ip`, фаервол, либо она не в вашей сети |
| пришла на брокер, но не качает образ | формат команды — тогда `--try-variants` |
| скачала, но не загрузилась | формат образа: возьмите другой вариант (`ota1`/`ota2`) |

Скрипт при неудаче печатает все топики, на которые розетка подписалась, и
её сообщения — по ним видно реальные имена топиков.

Кирпича быть не должно: образ пишется во второй слот, и при неверном
формате загрузчик откатывается на рабочий первый (`Invalid FW Image Signature!`
в UART-логе).

## Запасной путь по проводам

```
ATOTA=http://<IP-хоста>:8000/ВАШ_ОБРАЗ.bin
```

в AT-консоли розетки (USB-UART на TX/RX/GND). Программатор и режим загрузчика
не нужны.
